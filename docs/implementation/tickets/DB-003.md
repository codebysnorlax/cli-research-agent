## Purpose
Create the event log repository — the audit trail for every state transition and significant action. Every important event produces an immutable log entry. This enables answering: **"Why did this email get sent?"**

## Current State
Schema exists (DB-001). No event logging code.

## Required Change
Create event log repository per doc 06 §5:
1. `logEvent(db, jobId, eventType, metadata)` — insert event record
2. `getJobHistory(db, jobId)` — full event timeline for a job
3. `getRecentEvents(db, limit)` — latest events across all jobs

## Scope

## Out of Scope

## Interfaces / Contracts
```javascript
export function logEvent(db, jobId, eventType, metadata = {})
// Inserts: { job_id, event_type, timestamp (ISO 8601 UTC), metadata (JSON string) }
// Returns: event id (autoincrement)

export function getJobHistory(db, jobId)
// Returns: event[] ordered by timestamp ASC

export function getRecentEvents(db, limit = 50)
// Returns: event[] ordered by timestamp DESC, limited
```

## Data Changes
All operations on `email_events` table. No schema changes.

## Behavior
- `logEvent` stores `metadata` as JSON string
- `timestamp` defaults to current UTC ISO 8601
- Events are append-only — never updated or deleted
- `getJobHistory` returns chronological order for a single job
- `getRecentEvents` returns reverse-chronological across all jobs

## Security
- Parameterized queries only
- Events are immutable (no UPDATE/DELETE exposed)

## Failure Cases
- `logEvent` with non-existent jobId → foreign key constraint error
- `logEvent` with invalid eventType → should still insert (event types are validated at caller level)

## Tests Required
